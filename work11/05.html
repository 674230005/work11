จุดประสงค์การเรียนรู้:

  • อธิบาย Repository Pattern และการแยกสัญญาออกจากการจัดเก็บข้อมูลได้
  • อธิบายความแตกต่างของ Entity กับ Value Object ได้
  • เขียน Repository ที่ปกป้องข้อมูลภายในจากการแก้ไขภายนอกได้

Interface ทำหน้าที่เป็น Indirection เพื่อปกป้อง Use Case จากการเปลี่ยนแปลงของเทคโนโลยีการจัดเก็บข้อมูล

ส่วนที่ 1: อ่านแผนภาพแล้วตอบคำถาม (10 คะแนน)

1) «interface» UserRepository ทำหน้าที่อะไรในระบบ และเหตุใดต้องแยก “สัญญา” ออกจาก “implementation” 2 คะแนน

คำตอบ: UserRepository เป็นสัญญาสำหรับ save, findById และ all; แยกสัญญาจาก implementation ทำให้เปลี่ยนวิธีเก็บข้อมูลโดยไม่กระทบผู้เรียก

2) ลูกศร “Protected Variations” จาก InMemoryUserRepository ชี้ไปยัง UserRepository หมายถึงอะไร 2 คะแนน

คำตอบ: โค้ดส่วนอื่นพึ่งพา UserRepository ไม่พึ่ง InMemoryUserRepository โดยตรง จึงเปลี่ยนไปใช้ฐานข้อมูลได้

3) ป้าย “Information Hiding” บนลูกศรจาก InMemoryUserRepository ไปยัง User สื่อความหมายว่าอย่างไร 2 คะแนน

คำตอบ: การซ่อนอาร์เรย์ users และคืนข้อมูลผ่านเมธอดป้องกันไม่ให้โค้ดภายนอกรู้รายละเอียดการจัดเก็บภายใน

4) User ถูกกำกับว่า «Entity» ซึ่งแตกต่างจาก Value Object อย่างไร จงอธิบายพร้อมยกตัวอย่าง 2 คะแนน

คำตอบ: Entity มีเอกลักษณ์คงที่ เช่น User ที่ระบุด้วย id; Value Object วัดจากค่า เช่น Email และไม่มี identity ของตัวเอง

5) เมธอด findById คืนค่าเป็น UserOrNull การคืน null สื่อความหมายว่าอย่างไร 1 คะแนน

คำตอบ: ไม่พบ id ที่ระบุ จึงคืน null เพื่อสื่อว่าไม่มีผู้ใช้รายนั้น

6) หากในอนาคตต้องการเปลี่ยนไปเก็บข้อมูลในฐานข้อมูล MySQL โค้ดส่วนใดต้องเปลี่ยนแปลงบ้าง 1 คะแนน

คำตอบ: เพิ่ม MySQLUserRepository ที่ implements UserRepository แล้วเปลี่ยนการประกอบระบบให้ใช้ implementation ใหม่

ส่วนที่ 2: วิเคราะห์โค้ด (10 คะแนน)

พิจารณาโค้ดต่อไปนี้ แล้วตอบคำถาม

<?php declare(strict_types=1);

final readonly class User
{
    public function __construct(
        public int $id,
        public string $email,
    ) {}
}

interface UserRepository
{
    public function save(User $user): void;

    public function findById(int $id): ?User;

    /** @return list<User> */
    public function all(): array;
}

final class InMemoryUserRepository implements UserRepository
{
    /** @var array<int, User> */
    private array $users = [];

    public function save(User $user): void
    {
        $this->users[$user->id] = $user;
    }

    public function findById(int $id): ?User
    {
        return $this->users[$id] ?? null;
    }

    public function all(): array
    {
        return array_values($this->users);
    }
}

$repo = new InMemoryUserRepository();
$repo->save(new User(680001, 'student@example.ac.th'));
$repo->save(new User(680002, 'student2@example.ac.th'));

$student = $repo->findById(680001);
echo $student?->email, PHP_EOL;
echo sprintf('จำนวนนักศึกษาทั้งหมด: %d คน', count($repo->all())), PHP_EOL;

1) เหตุใดเมธอด all() จึงใช้ array_values() แทนการคืน $this->users โดยตรง ป้องกันความเสี่ยงใด 3 คะแนน

คำตอบ: array_values() คืนรายการเป็นอาร์เรย์ดัชนีต่อเนื่อง ไม่เปิดเผย key ภายในที่ใช้ id และไม่ให้ผู้เรียกพึ่งโครงสร้างเก็บข้อมูล

2) การเรียก $repo->findById(999999) ให้ผลลัพธ์เป็นอะไร และโค้ดบรรทัดใดรับผิดชอบ 2 คะแนน

คำตอบ: คืน null จากนิพจน์ $this->users[$id] ?? null เมื่อไม่พบ key

3) หาก save ผู้ใช้ที่มี id ซ้ำกับข้อมูลเดิมจะเกิดอะไรขึ้น เพราะเหตุใด 3 คะแนน

คำตอบ: ตามโค้ด save() ใช้ id เป็น key จึงเขียนทับข้อมูลเดิมที่มี id เดียวกัน ไม่ได้ปฏิเสธ id ซ้ำ เว้นแต่เพิ่มการตรวจสอบ

4) เหตุใด User จึงเป็น final readonly class การออกแบบนี้ดีต่อระบบอย่างไร 2 คะแนน

คำตอบ: final ป้องกันการสืบทอดเปลี่ยนพฤติกรรม ส่วน readonly ป้องกันการแก้ property หลังสร้าง ทำให้ข้อมูลผู้ใช้คงที่

ส่วนที่ 5: สะท้อนคิดเชิงออกแบบ OOAD (6 คะแนน)

1) Repository Pattern ช่วยลด coupling ระหว่าง Use Case กับเทคโนโลยีการจัดเก็บข้อมูลอย่างไร 2 คะแนน

คำตอบ: Repository แยก logic ธุรกิจจากรายละเอียดฐานข้อมูล ทำให้เปลี่ยนจากอาร์เรย์เป็น MySQL โดยไม่ต้องแก้ Use Case

2) “จุดที่เปลี่ยนแปลง” ในข้อนี้คืออะไร และการออกแบบนี้ปกป้องระบบด้วย Protected Variations อย่างไร 2 คะแนน

คำตอบ: จุดเปลี่ยนคือเทคโนโลยีจัดเก็บข้อมูล; interface UserRepository เป็น abstraction ที่ปกป้องส่วนอื่นจากการเปลี่ยน implementation

3) เมื่อต้องเขียน Unit Test ให้ RegisterUserService Interface UserRepository ช่วยให้การทดสอบง่ายขึ้นอย่างไร 2 คะแนน

คำตอบ: สร้าง FakeUserRepository ที่ implements interface เดียวกันเพื่อเก็บข้อมูลในหน่วยความจำและตรวจผลได้โดยไม่ต้องใช้ฐานข้อมูลจริง
